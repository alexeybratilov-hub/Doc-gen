## 2. Роли инструментов

### Qwen Coder — основной исполнитель
- Читает исходники перед любыми правками; работает только внутри `/workspace`.
- Вносит минимально необходимые точечные изменения (не переписывает модули целиком без согласования).
- Проверяет доступными средствами (`tsc --noEmit`, сборка) и честно отделяет выполненное от непроверенного.
- Обновляет документацию постоянного контекста, если задача её затрагивает.
- Готовит структурированный отчёт по итогам задачи.
- **Не делает commit/push без явного разрешения владельца.** Отчёт «коммит не выполнялся» относится к операции Qwen, а не к итоговому состоянию репозитория (владелец коммитит вручную).

### Google AI Studio — независимый аудитор
- Самостоятельно изучает актуальное состояние репозитория; **не доверяет отчёту Qwen на слово**, проверяет код.
- Использует предпросмотр приложения для проверки UI-сценариев, где это возможно.
- Выявляет регрессии; по каждому пункту указывает: подтверждено / не подтверждено / требует уточнения, серьёзность и условия воспроизведения.
- Отличает подтверждённые проблемы от предположений; известные ограничения (см. §7) не оформляет как новые дефекты.
- По умолчанию формирует **отчёт**, а не исправления; большие модули не переписывает без согласования.

### Владелец проекта
- Координирует этапы: решает, кто и когда работает (последовательно, не одновременно).
- Вручную коммитит изменения после каждой операции Qwen и синхронизирует с GitHub.
- Принимает решения по открытым вопросам Q1–Q5 (`TASK_STATUS.md`).
- Даёт разрешение на commit/push и разрушительные Git-операции.

## 3. Порядок передачи работы через GitHub

1. **GitHub — общая точка передачи состояния.** Каждый инструмент начинает работу со свежего состояния репозитория (клон/ветка после пуша владельца), а не из памяти предыдущего чата.
2. **Последовательность обязательна:** Qwen Coder и Google AI Studio никогда не редактируют репозиторий одновременно. Активная роль — одна за раз, по решению владельца.
3. **Коммиты:** владелец вручную коммитит после каждой операции Qwen. Поэтому формулировки инструментов «я не коммитил» не означают, что изменение отсутствует в репозитории.
4. **Проверка перед началом:** каждый инструмент выполняет `git status` и при наличии незакоммиченных изменений сообщает об этом владельцу и **не перезаписывает их**.
5. **Запрещено без явного разрешения:** commit, push, merge, reset, rebase, clean, удаление файлов, изменение зависимостей.
6. **Передача результатов:** отчёт исполнителя → решение владельца → коммит/пуш → следующий инструмент забирает обновлённое состояние.

## 6. Формат отчёта Google AI Studio

- **Что проверялось** — список пунктов чек-листа (или его часть).
- **Что подтверждено** кодом / предпросмотром — со ссылками файл:строка.
- **Что не подтверждено** — и при каких условиях воспроизводится.
- **Серьёзность** каждого выявленного дефекта (высокая/средняя/низкая).
- **Подтверждённые проблемы vs предположения** — явно разделены.
- **Точные задания для исправления** — файл, функция, ожидаемое поведение.
- **Что осталось непроверенным** и почему (нет ОС Windows, нет доступа к предпросмотру и т.п.).

## 7. Правила для аудитора

1. Сначала отчёт, потом исправления. Большие модули не переписывать без согласования с владельцем.
2. Не доверять отчёту Qwen на слово — проверять фактический код.
3. Не смешивать известные ограничения и открытые вопросы (R3, R4, R5, R6, R7, R11/Q1, R13) с новыми регрессиями: первые фиксировать как «подтверждение известного состояния», вторые — как дефекты.
4. Не делать commit и push.
5. Не менять схему данных, зависимости и конфигурацию в рамках аудита.
